# 成员 C：维修工单与备件管理

## 模块职责

- 接收预警或人工报修，生成稳定且唯一的 `OrderId`；
- 管理确认、派发、接单、维修、等待备件、试运行、验收、关闭和取消；
- 管理备件申请、审批、预留、领用、退回和库存流水；
- 向成员 A 反馈设备状态；
- 向成员 B 反馈实际根因、措施和维修效果。
- 使用成员 D 的统一身份、通知和质量门禁完成联调交付。

## 对外契约

- 调用：设备查询（C-INT-01）；
- 接收：`WarningRaised`（C-INT-02）；
- 发送：`EquipmentStatusChanged`（C-INT-03）；
- 发送：`MaintenanceConclusionReported`（C-INT-04）。

## 实现前必须确定

- 工单状态机和各迁移的执行角色；
- `WarningId` 非空时的唯一约束与重复事件处理；
- 库存预留、释放和实际扣减的事务边界；
- 验收不通过时保留历史记录并返工的方式；
- 外部接口失败时的待同步和重试状态。

## 建议内部结构

```text
src/
├── domain/          # 工单、备件、验收、状态机
├── application/     # 建单、派单、维修、领退、验收用例
├── interfaces/      # HTTP/事件入口与展示接口
└── infrastructure/  # 数据库、消息、通知适配
tests/
```

不得自行维护另一套设备和预警权威数据；只保存建单时必要的业务快照。
