# 完成定义与联调清单

## 1. 功能任务完成定义

- [ ] 关联一个明确的 Issue 和需求编号
- [ ] 输入、输出、前置条件、正常流程和异常流程已实现
- [ ] 关键业务规则在服务端校验，不只依赖前端
- [ ] 单元测试或模块测试覆盖新增行为
- [ ] 错误信息可定位且不泄漏敏感信息
- [ ] 文档、接口示例、数据模型与代码一致
- [ ] 自动检查通过且至少一名队友批准

## 2. 契约任务完成定义

- [ ] 提供方与调用方已经确认字段语义
- [ ] OpenAPI 或 JSON Schema 已更新
- [ ] 正常示例与异常示例已更新
- [ ] 说明向后兼容、迁移和回滚方式
- [ ] 同一业务重试的幂等行为明确
- [ ] 版本号和弃用计划明确

## 3. 端到端联调清单

### E2E-01 高风险自动派修

- [ ] D 提供统一测试身份、初始化环境并分配 `TraceId`
- [ ] A 提供存在且可查询的 `EquipmentId`
- [ ] B 发送唯一 `EventId`、`WarningId` 和高风险信息
- [ ] C 只创建一张待确认工单并返回 `OrderId`
- [ ] 重放同一事件不重复建单

### E2E-02 维修开始

- [ ] D 确认四个服务健康检查通过并采集联调日志
- [ ] C 记录责任工程师和开始时间
- [ ] C 向 A 发送 `MAINTAINING` 状态事件
- [ ] A 返回处理确认并展示一致状态
- [ ] B 保留预警为处理中，不提前关闭

### E2E-03 缺少备件

- [ ] D 保留同一 `TraceId` 下的跨模块调用与重试证据
- [ ] C 将工单置为 `WAITING_PARTS`
- [ ] 申请、审批、预留、到货和领用记录可追踪
- [ ] A 保持设备维修状态
- [ ] B 保留原预警，备件到位后恢复原工单而非新建工单

### E2E-04 验收关闭

- [ ] D 验证通知、失败重试和最终一致性，保存执行结果
- [ ] C 保存试运行、验收、实际根因和维修措施
- [ ] C 向 A 发送设备恢复状态
- [ ] C 向 B 发送维修结论
- [ ] A、B 均返回确认；失败可重试且不产生副作用
- [ ] 工单归档后普通用户不能覆盖历史事实

## 5. 发布前检查

- [ ] `main` 是唯一发布来源
- [ ] 四个模块/服务记录的版本或 Commit SHA 明确
- [ ] 数据库迁移顺序已验证
- [ ] 环境变量清单齐全且没有真实秘密进入仓库
- [ ] 备份与回滚步骤经过一次演练
- [ ] 演示数据为虚构或脱敏数据
- [ ] 核心 E2E 场景均有最近一次通过记录
