# 演示视频准备手册 · 可用流程与时间轴

> 编制日期：2026-10-12 | 分支：`feat/web-platform-ui`
> 用途：录演示视频前，照着这份文档走一遍即可，含**每步耗时**与**等待时间点**。

**访问地址**：`http://36.213.152.237:8888/`（公网）
**登录账号**：`USER-D-001` / `demo123456`（或点登录页的快捷按钮切换 7 个角色）

## 一、系统一句话

四服务闭环：**A 设备监测 → B 故障预警 → C 维修工单 → D 集成与权限**，
设备监测到异常 → 自动评分预警 → 自动建单 → 人工处置 → 恢复正常，全链路走真实接口。

| 服务 | 端口 | 职责 |
|---|---|---|
| A 设备监测 | 8101 | 设备主数据、遥测采集、异常注入 |
| B 故障预警 | 8102 | 健康评分、风险分级、预警生成 |
| C 维修工单 | 8103 | 工单流转、备件领用 |
| D 集成质量 | 8104 | 登录鉴权、权限、通知、审计 |

## 二、核心演示流程（主推，约 4 分钟）

### 流程 1：异常注入 → 全链路闭环 ⭐ 最重要

| # | 操作 | 预期 | 耗时 |
|---|---|---|---|
| 1 | 登录（点快捷按钮「系统管理员 USER-D-001」→ 登录） | 进入驾驶舱首页 | 10s |
| 2 | 左侧导航「设备管理 → 设备资产台账」 | 8 台设备表格 | 5s |
| 3 | **点击任一设备行** | 进入「设备详情」，6 个 Tab | 5s |
| 4 | 切到「遥测趋势」Tab | 3 张图（温度/振动/电流） | 5s |
| 5 | 展开「模拟数据注入工作台」→ 点**注入异常（严重）** | 逐条打印链路日志 | 5s |
| 6 | ⏳ **等待 2.5 秒**（脚本内部固定等待） | A 写遥测 → B 评分建预警 → C 自动建单 | **2.5s** |
| 7 | 看日志面板 | 每步调用的真实接口与结果 | 10s |
| 8 | 切「预警记录」Tab | 新增一条 CRITICAL 预警 | 5s |
| 9 | 切「维修工单」Tab | 新增一张 P1 工单（待确认） | 5s |

> **一键替代**：顶栏「🎬 演示」按钮 = 同一套流程，弹窗确认后自动跑完，适合视频里快速展示。
>
> ⚠️ **注意**：一键演示固定取**第一台 `enabled !== false` 的设备**，不是当前选中的设备。

### 流程 2：工单全生命周期流转（6 状态）

**状态机**（界面按权限渲染按钮，无权限的按钮是灰的）：

```
待确认 ──确认──▶ 待派单 ──派单──▶ 待接单 ──接单──▶ 待维修
                                                      │
                                                   开始维修
                                                      ▼
待验收 ◀──提交验收── 维修中 ──等待备件──▶ 等待备件
   │                              ◀──恢复维修──┘
   ├─验收通过─▶ 已完成
   └─验收驳回─▶ 维修中（返工）
```

任意状态可「取消工单」→ 已取消。

| # | 角色 | 操作 | 状态变化 | 耗时 |
|---|---|---|---|---|
| 1 | 维修主管 `USER-C-001` | 确认工单 | 待确认 → 待派单 | 8s |
| 2 | 维修主管 | 派单（选工程师） | 待派单 → 待接单 | 10s |
| 3 | 工程师 `USER-C-002` | 接单 | 待接单 → 待维修 | 8s |
| 4 | 工程师 | 开始维修 | 待维修 → 维修中 | 8s |
| 5 | 工程师 | 提交验收（填根因/措施） | 维修中 → 待验收 | 15s |
| 6 | 验收员 `USER-C-004` | 验收通过 | 待验收 → 已完成 | 10s |

> **看板页**（「维修管理 → 工单看板 Kanban」）点卡片可直达工单详情，流转更直观。
> **切换角色**：退出登录 → 登录页点对应快捷按钮，无需记账号。
> **不想中途换角色？** 全程用 `USER-D-001`（`ADMIN_ALL`）即可走完 6 步，
> 所有动作按钮都会亮；想演示权限差异时再换成下面的细分角色。

**权限对照**（演示多角色时用）：

| 动作 | 权限码 | 拥有者 |
|---|---|---|
| 确认 / 派单 / 取消 | `WORK_ORDER_CONFIRM` / `ASSIGN` / `CANCEL` | 维修主管、管理员 |
| 接单 / 开始维修 / 提交验收 | `WORK_ORDER_ACCEPT` / `MAINTAIN` | 工程师 |
| 验收通过 / 驳回 | `WORK_ORDER_INSPECT` | 验收员 |

### 流程 4：预警处置

> ⚠️ **必须用有 `WARNING_READ` 权限的角色**，否则整个页面只剩一句"B 服务对
> /api/v1/warnings 做了服务端强制鉴权"，**表格和三个 Tab 都不渲染**，
> 会以为功能没做。
> **能用**：`USER-D-001`（管理员）、`USER-B-001`（预警分析师）。
> **不能看**：`USER-C-001` 维修主管、`USER-C-002` 工程师。

| # | 操作 | 预期 | 耗时 |
|---|---|---|---|
| 1 | 「健康与预警 → 预警中心」 | 5 张 KPI 卡 + 预警台账 | 5s |

**预警状态机**：待处理 → 已确认 → 已转工单 → 已闭环（或已取消）

### 流程 5：备件领用（配合工单）

**状态机**：

```
待审批 ──批准──▶ 已批准 ──预留库存──▶ 已预留 ──发料──▶ 已发料
   │                                                      │
 驳回                                                   退料 / 关单
   ▼                                                      ▼
已驳回                                            部分退料 → 已关单
```

| # | 角色 | 操作 | 耗时 |
|---|---|---|---|
| 1 | — | 发起申请（「备件管理 → 领用申请」点**＋ 新建申请**，或从工单详情发起） | 15s |
| 2 | 仓管员 `USER-C-003` | 批准申请 | 8s |
| 3 | 仓管员 | 预留库存 | 8s |
| 4 | 仓管员 | 发料（填实发量） | 10s |
| 5 | 仓管员 | 关单 | 5s |

## 四、时间相关参数（录屏节奏靠这些）

| 参数 | 值 | 说明 |
|---|---|---|
| 页面轮询 | **5 秒** | 仅当前页声明了 `poll` 才拉取，**不重渲染整页** |
| 注入后等待 | **2.5 秒** | 注入异常/恢复数据后，等 B/C 完成联动 |
| 状态提示自动隐藏 | 异常 4s / 恢复 3s | 注入后的浮动提示 |
| 工单流转 | 人工点击 | 无自动推进，节奏由你控制 |

> **录屏建议**：第 6 步的 2.5 秒等待，正好用语音解释"系统正在自动评估并建单"。
> 如果觉得 2.5 秒空等难看，可提前把话术铺好，或后期剪掉。

## 六、常见坑

1. **改了前端但界面没变**：nginx 对 JS 只发 `ETag`、不发 `Cache-Control`，浏览器会吃缓存。**Ctrl+F5 硬刷新**。服务端不用重启（纯静态文件）。
2. **按钮是灰的**：不是 bug，是当前角色没有对应权限码。换角色或换 `USER-D-001`（`ADMIN_ALL`）。
3. **注入没反应**：确认 A 服务（8101）在跑；注入要带内部令牌，服务没起来会失败。
4. **详情页 6 Tab 只有颜色变**：已修复（`00b94c6`）。若还出现，说明吃了旧缓存，硬刷新。
5. **筛选后显示"确认 A 服务已启动"**：已修复（`ef13b0a`）。还出现就硬刷新。
