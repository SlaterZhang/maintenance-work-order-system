# 模块边界与责任矩阵

## 1. 责任边界

### 成员 A：设备资产与运行监测

负责：

- 设备主数据、类型、生产线和责任部门；
- 运行数据接入与设备当前状态；
- `EquipmentId` 的生成或维护规则；
- 响应设备查询；
- 接收 C 发出的维修状态事件并更新设备状态。

不负责：风险等级判定、工单生命周期、备件库存业务。

### 成员 B：故障预警与健康评估

负责：

- 预警事件、健康分、风险等级和疑似故障；
- `WarningId` 的生成和幂等性；
- 向 C 发布高风险或严重预警；
- 接收 C 的维修结论并关闭、修正或标注预警。

不负责：设备主档、工单派发、备件领退。

### 成员 C：维修工单与备件管理

负责：

- 接收预警或人工报修并创建 `OrderId`；
- 工单确认、派发、接单、维修、试运行、验收和归档；
- 备件申请、审批、预留、领用、退回和库存流水；
- 向 A 反馈设备状态，向 B 反馈实际根因和维修结论。

不负责：传感器采集协议、健康评分算法、设备主数据的权威维护。

### 成员 D：系统集成与质量保障

负责：

- 统一身份、角色、权限与通知能力；
- 维护跨模块契约检查、Mock、CI/CD 和质量门禁；
- 组织端到端联调，记录基线 Commit、`TraceId` 和验证证据；
- 维护部署配置、环境变量清单、运行日志和基础可观测性；
- 发现接口、状态、枚举或版本不一致时阻止不安全合并。

不负责：单方面决定设备、预警、工单和备件的业务语义；业务规则仍由 A/B/C 对应负责人确认。

## 2. 数据所有权

| 数据 | 权威成员 | 其他成员的使用方式 | 禁止事项 |
| --- | --- | --- | --- |
| `EquipmentId` 与设备档案 | A | 查询接口或设备事件 | B/C 自建另一套设备编号 |
| `WarningId` 与风险信息 | B | 预警事件 | A/C 修改风险算法输出历史 |
| `OrderId` 与工单状态 | C | 状态与结论事件 | A/B 直接修改工单表 |
| 用户、角色、通知 | D | 统一 `UserId`、角色编码和通知入口 | A/B/C 分别维护同一用户密码 |
| 公共枚举与事件包络 | 四人共同，D 维护门禁 | `contracts/` 唯一定义 | 在代码里静默增加新枚举值 |

## 3. RACI 表

说明：R=执行，A=最终负责，C=必须协商，I=知会。

| 工作项 | 成员 A | 成员 B | 成员 C | 成员 D |
| --- | --- | --- | --- | --- |
| 设备档案与状态 | A/R | I | C | I |
| 健康评分与故障预警 | C | A/R | C | I |
| 工单与备件闭环 | C | C | A/R | I |
| `C-INT-01` 设备查询 | A/R | I | C | R（契约测试） |
| `C-INT-02` 健康评估 | R | A/R | I | R（契约测试） |
| `C-INT-03` 预警事件 | I | A/R | C | R（契约测试） |
| `C-INT-04` 维修状态事件 | C | I | A/R | R（契约测试） |
| `C-INT-05` 维修结论事件 | I | C | A/R | R（契约测试） |
| `C-INT-06` 身份权限 | C | C | C | A/R |
| `C-INT-07` 通知 | C | C | C | A/R |
| 公共枚举与接口版本 | C | C | C | R（门禁维护） |
| 端到端验收 | R | R | R | A/R（组织与留证） |

## 4. 目录所有权

```text
apps/
├── equipment-monitoring/   # A
├── fault-warning/          # B
├── maintenance/            # C
└── integration-quality/    # D
contracts/                  # 四人共同确认，D 维护质量门禁
shared/                     # 四人共同确认，谨慎添加代码
tests/                      # D 主责契约和端到端测试
docs/                       # 决策、需求和协作证据
```

只有在确实被多个模块共同使用、语义完全相同且版本同步时，代码才放入 `shared/`。业务实体不应为了“少写几行”被强行共用。
