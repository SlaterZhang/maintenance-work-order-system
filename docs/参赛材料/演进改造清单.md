## 1. P0：影子双轨对账（约 3–5 天，无需 GPU）

**为什么最优先**：契约与代码已经为它准备好了，改动最小、收益最大，且能立刻产出可量化的对比证据。

**已具备的前置条件（已实测确认）**
- `modelVersion` 是预警契约的**必填字段**：`contracts/schemas/warning-raised.payload.schema.json:14`（required）、`:57`（定义）。
- 当前值来源：`apps/fault-warning/src/config.py:28` `model_version: str = "rule-engine-1.0.0"`；`apps/fault-warning/src/domain/scoring.py:48` `MODEL_VERSION = "rule-engine-1.0.0"`。
  - **坑**：`apps/fault-warning/src/config.py:13` 注明 `protected_namespaces` 已置空，因为 `model_version` 与 pydantic 的 `model_` 保护前缀冲突——新增 `model_*` 字段时别踩这个。
- 降级范式已固化：`apps/fault-warning/src/domain/trend.py:6-7` 注释「样本不足 / A 不可达 → UNKNOWN，所有预测字段为 null——趋势是增强信息，**绝不阻塞评估主链路**（P0-1 的教训）」。
- 规则引擎是**纯函数**：`apps/fault-warning/src/domain/scoring.py` 注释「无随机、无时间依赖（时间由调用方传入），可重复验证」→ 离线回放对账极易做。

**改造项**

1. **新增影子结果表**（B 服务）
   - 文件：`apps/fault-warning/src/domain/models.py`
   - 新表 `model_shadow_result`：`id` / `evaluation_id` / `equipment_id` / `model_version`（如 `ml-shadow-0.1.0`）/ `health_score` / `risk_level` / `suspected_fault` / `created_at`。
   - **迁移路径（AGENTS.md 硬约定）**：SQLAlchemy 新表必须覆盖重建路径 —— `init_db()` 走 `Base.metadata.create_all()`，新表会自动建；演示库可 `python3 scripts/reset_demo.py` 清库重建。**旧库升级需删库重建**（`create_all` 只建表不加列）。

2. **影子内核接口**（B 服务）
   - 文件：`apps/fault-warning/src/domain/`（建议新建 `shadow.py`）
   - 定义 `predict_shadow(sample: dict) -> ShadowResult | None`；**任何异常一律 `return None`**（复用 `trend.py` 的降级范式）。
   - 首版实现可以是「阈值微调的规则变体」或 Isolation Forest（见 P0-2），先跑通链路。

3. **评估用例旁路调用**（B 服务）
   - 文件：`apps/fault-warning/src/application/evaluation_service.py`
   - 在现有规则评分之后、写库之前插入影子调用；**影子结果只写 `model_shadow_result` 表，绝不参与 `_obtain_warning` 的建单判断**。

4. **对账脚本**
   - 文件：新建 `scripts/shadow_reconcile.py`
   - 读 `health_evaluation`（规则结论）与 `model_shadow_result`（影子结论），按 `evaluation_id` join，输出：一致率（风险等级完全一致占比）、漏报数（影子 HIGH+ 而规则 LOW）、误报数（影子 LOW 而规则 HIGH+）、分设备类型分组统计。
   - 输出 Markdown 报告到 `docs/`，作为「AI 不越权」的量化证据。

**验收标准**
- 不影响现有 222 项 B 测试（全绿）。
- `check_repo.py --strict` 仍 34 项 0 警告。
- 对账脚本在演示数据上能跑出报告，且影子通道**故意抛异常时评估主链路仍正常返回**（需专门写一个测试证明这点）。

## 2. P0：无监督异常检测（约 5–7 天）

**分两步，先零训练基线再上深度模型**——避免一上来就引入 torch。

**第 1 步：零训练基线（1–2 天）**
- 依赖：`scikit-learn`（Isolation Forest）、`numpy`。
- 输入：`apps/fault-warning/src/interfaces/clients/member_a.py` 的 `fetch_recent_telemetry`（已有，失败返回 `None`）。
- 输出：异常分写入 P0-1 的影子表。
- **注意**：样本不足时返回 `None`，不发结论。

**第 2 步：LSTM 自编码器（3–5 天）**
- 依赖：`torch`（CPU 版即可）。
- 结构：`LSTM-AE`（编码器-解码器，重建误差作异常分）。选它的理由是**可单机训练、参数量小、无需故障标注**。
- 训练数据：A 服务遥测历史。
- **指标口径警告**：报告指标时**不要用 Point Adjustment 协议**——该协议会系统性高估性能（见 TSB-AD, NeurIPS 2024）。改用 **AUC-PR / AUC-ROC / F1**。

**参考模型（不要求全部实现，按需选一）**
| 模型 | 机构 / 年份 | 定位 |
|---|---|---|
| Isolation Forest | 经典基线 | 零训练、可单机 |
| LSTM-AE | TCS Research, 2016 (arXiv:1607.00148) | 轻量、可单机训练 |
| USAD | Orange Labs + EURECOM, KDD 2020 | 对抗式自编码器 |
| TranAD | VLDB 2022 | 基于 Transformer 的对抗训练 |
| Anomaly Transformer | 清华 THUML, ICLR 2022 Spotlight (arXiv:2110.02642) | 关联差异机制，需 GPU |

**验收标准**：在留出集上报 AUC-PR / AUC-ROC / F1，并说明点调整协议未使用；影子通道仍不影响主链路。

## 3. P0：预测结果的不确定性量化（约 3–4 天）

**为什么重要**：维修排期需要的是**区间与置信度**，一个确定性数字会误导决策。

**改造项**
1. 把趋势外推从单点改为区间
   - 文件：`apps/fault-warning/src/domain/trend.py`（已有线性外推与 `PROJECTION_HOURS`）
   - 方法：**分位数回归**（quantile regression）或 **Conformal Prediction**（分布无关、有覆盖保证）。
   - 输出：P10 / P50 / P90 触阈值天数。
2. 契约同步（**必须一并做**）
   - `contracts/schemas/warning-raised.payload.schema.json` 或健康评估响应 schema 增字段。
   - `contracts/openapi.yaml` 对应 schema 同步。
   - `contracts/examples/` 示例报文同步。
   - `scripts/check_repo.py` 的 `REQUIRED_PATHS` / `EVENTS` 若涉及必需文件，需一并更新（**历史教训：漏改会让 CI 首步直接 exit 1**）。
3. 前端展示
   - 文件：`web/js/equipment.js`（趋势图）
   - 外推段改为区间带状图（ECharts `markArea` 或自定义 series），并标注置信水平。

**验收标准**：区间在留出集上的经验覆盖率接近名义覆盖率（如 P10–P90 应覆盖约 80%）；契约校验通过。

## 4. P1：可解释归因（约 3–5 天）

**关键澄清（务必写对）**：**注意力权重不等于解释**——Jain & Wallace (NAACL 2019) 已证明注意力可被大幅扰动而几乎不改变输出。注意力只能作为工程师的**探查线索**，正式归因用 SHAP / Integrated Gradients。

**改造项**
- 依赖：`shap`（CPU 可跑）。
- 对 P0-2 的异常检测模型（或对规则引擎的代理模型）做 SHAP 归因，**归因到具体传感器与具体时段**。
- 输出写入预警的 `evidence` 字段（若契约无此字段，按 §3.2 的流程新增）。
- 前端在预警详情卡显示「判断依据」列表，供维修人员复核。

**验收标准**：归因结果对同一输入稳定可复现；界面上能看到「哪个传感器、哪个时段、贡献多少」；文档中不出现「用注意力解释」的表述。

   - 映射：**A 模块** = ①②；**B 模块** = ③④；**趋势外推 + C 模块** = ⑤⑥。

2. **标准引用校准**
   - ✅ 已改：`apps/fault-warning/src/domain/scoring.py:39` 原引 `ISO 10816`，现为 `ISO 20816-1:2016（其前身为 ISO 10816）`。
   - 全仓已无其它 `ISO 10816` 引用（grep 确认）。
   - **背景**：ISO 10816 已于 2016 年被 ISO 20816 取代（ISO 20816-1:2016）。

3. **三处数字滞后修正**
   - `docs/参赛材料/作品说明文档.md`（118 行）写的是「20 路径 / 24 操作、32 项门禁、四类事件」。

## 7. P2：轻量时序基础模型验证（约 3–5 天）

**只做 CPU 可行性验证，不承诺完整规模模型微调。**

- **为什么选这两个**：**IBM TinyTimeMixer（1M–8M 参数）** 与 **TSPulse（约 1M 参数）** 是**为无 GPU 推理设计**的时序基础模型家族，是本环境唯一现实可行的 TSFM 选项。
- 场景：**新设备冷启动**——无历史数据时提供零样本预测基线。
- 完整规模模型（TimesFM 200M/330M、Chronos、Moirai、MOMENT、Timer）**标注为长期方向，不在近期承诺范围**。
- 部署链路：ONNX 导出 → ONNX Runtime CPU 推理。

**验收标准**：能与零样本基线对比（MAE/RMSE），并说明未使用 GPU。

## 8. P2：维修知识库 RAG（约 5–7 天）

- 数据：C 服务 `work_order` 表（`root_cause` / `measures` / `maintenance_result` / `effective`）+ `docs/` 手册。
- 做法：向量化 → 向量检索 → **单轮**检索增强生成。
- **边界明确**：仅做单轮检索问答，**不做多智能体协作、不做自主建单**；数值判断仍由时序模型负责，不让 LLM 做数值决策。
- 理由：LLM 缺乏对物理量纲与设备工况的精确感知；工业场景要求可追溯、可复现、可审计；中小制造企业算力预算有限。

## 11. 依赖隔离方案（重要）

**不要**把 numpy/torch/shap 直接装进规则引擎所在进程的必需依赖里。

推荐做法（按侵入性从低到高）：
1. **可选依赖 + 惰性导入**：ML 依赖放进单独文件（如 `requirements-ml.txt`），代码内 `try: import torch except ImportError: return None`，复用 `trend.py` 的降级范式。
2. **独立进程**：新建 `apps/pdm-ml`（不在四服务契约内），通过内部 HTTP 或 Unix socket 提供推理，B 服务只在影子通道调用它。
3. 无论哪种，**A / C / D 与规则引擎主链路不得受影响**，且 `check_repo.py` 门禁必须继续通过。

---

## 12. 通用工程纪律（每次改造都要遵守）

- **改 SQLAlchemy 模型必须给迁移路径**。`init_db()` 走 `create_all()`，**只建表、不加列**；演示库可 `python3 scripts/reset_demo.py` 清库重建。
- **改代码后必须重启**：`systemctl restart ims-<a|b|c|d>` 或 `bash scripts/start_all.sh`。
- **契约变更四件套**：OpenAPI 路径 + Schema + 示例报文 + 枚举，再更新 `contracts/README.md` 登记表与 `contracts/http/local-api.http` 联调请求，**并检查 `scripts/check_repo.py` 的 `REQUIRED_PATHS` / `EVENTS`**（漏改 → CI 首步 exit 1）。
- **提交信息格式**：`^(feat|fix|docs|test|refactor|chore|ci|build|perf|revert)\((a|b|c|d|shared|contract|docs)\): .{4,72}$`，总长 ≤100，末尾不加句号。**scope 只有 9 个白名单值**（无 `web`、无复合 scope 如 `b,c`）。
- **测试必须分开跑**：B 与 C 的 `tests/conftest.py` 同名，混跑会触发 `_pytest.pathlib.ImportPathMismatchError`（既有特性）。
- **前端静态文件 chmod 644**，否则 nginx 返回 403。
