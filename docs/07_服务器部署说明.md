# 07 · 服务器部署说明（Debian / Ubuntu）

> 目标：把"工业设备智能运维与预测性维护系统"整套跑在远程 Linux 服务器上，
> 浏览器打开看板即可演示完整的"监测 → 预警 → 工单 → 恢复"闭环。
> Windows 本机的一键脚本是 `scripts/start_all.ps1`，服务器版等价物是 **`scripts/start_all.sh`**。

## 〇、总览

| 组件 | 目录 | 端口 | 说明 |
|------|------|------|------|
| A 设备监测 | apps/equipment-monitoring | 8101 | 设备档案 + 遥测采集 |
| B 故障预警 | apps/fault-warning | 8102 | 健康评估 + 预警事件 |
| C 维修工单 | apps/maintenance | 8103 | 工单状态机 + 备件 |
| D 身份通知 | apps/integration-quality | 8104 | 登录 JWT + 用户权限 |
| 前端看板 | web/dashboard.html | — | 零构建单页，浏览器直接打开 |

四服务同机部署、互调走本机回环（127.0.0.1），对外统一绑 `0.0.0.0`。

## 一、前置条件

- Debian 12+ 或 Ubuntu 22.04+（python3 >= 3.10；Debian 11 默认 python3.9 不满足，请先升级系统或自装 3.10+）
- 建议 2 核 4G 内存、5G 磁盘（含依赖安装空间）
- 服务器可访问公网（首次 pip 安装依赖；也可用国内镜像，见 FAQ）
- 能 SSH 登录服务器（TCP 22 入站）

## 二、部署步骤（裸机到服务可用）

### 1. 安装系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git curl
```

### 2. 获取代码

```bash
# 方式一：git clone（推荐）
git clone <你的仓库地址> maintenance-work-order-system
cd maintenance-work-order-system

# 方式二：本地上传（Windows 开发机打包后 scp）
# scp maintenance-work-order-system.zip user@<服务器IP>:~/
# unzip maintenance-work-order-system.zip && cd maintenance-work-order-system
```

### 3. 一键启动（自举 + 启动 + 健康等待）

```bash
bash scripts/start_all.sh
```

脚本幂等、可重复执行，首次运行会自动完成：
1. 检查 python3 >= 3.10（缺失/过低会给出 apt 安装提示并退出）；
2. 在仓库根创建共享虚拟环境 `.venv/`；
3. 按 `apps/*/requirements.txt` 安装四服务依赖；
4. 为四服务生成独立 `.env`（SQLite 数据库互不共用、内部令牌统一、
   `MEMBER_*_BASE` 指向本机回环，已存在则沿用不覆盖）；
5. 每服务一个后台 uvicorn 进程，**绑定 0.0.0.0**，日志写入 `logs/<代号>.log`，
   PID 写入 `.run/<代号>.pid`；
6. 轮询 `/health` 直到出现四行 `[OK  ]`（最长 60s，超时会列出未就绪服务
   并打印其日志尾部 20 行）。

### 4. 验证服务

```bash
# 四个 /health 全部返回 {"status":"UP",...}
curl http://127.0.0.1:8101/health
curl http://127.0.0.1:8102/health
curl http://127.0.0.1:8103/health
curl http://127.0.0.1:8104/health

# 随时查看状态 / 监听地址（应为 0.0.0.0:810x 而非 127.0.0.1:810x）
bash scripts/start_all.sh status
ss -ltn | grep -E ':(810[1-4])\b'
```

## 三、看板访问与演示

1. 在**本地电脑**浏览器打开 `web/dashboard.html`（从仓库下载该文件，或让服务器顺手起一个
   `python3 -m http.server 8090 --directory web` 后访问 `http://<服务器IP>:8090/dashboard.html`）；
2. 页面顶部四个服务地址输入框，把 `127.0.0.1` 改为 **服务器 IP**
   （如 `http://203.0.113.10:8101` ~ `:8104`）；
3. 点击「主管 USER-D-001」快捷按钮 → 登录（密码 `demo123456`）；
4. 按演示剧本操作：设备详情页「注入异常（严重）」→ 设备变红、预警产生、
   自动建单 → 主管确认/派单 → 工程师接单/维修/提交验收 → 主管验收通过 → 设备恢复绿。

## 四、端口清单（防火墙 / 云安全组放行）

| 端口 | 协议 | 用途 |
|------|------|------|
| 22 | TCP 入站 | SSH 部署管理 |
| 8101 | TCP 入站 | A 设备监测服务 |
| 8102 | TCP 入站 | B 故障预警服务 |
| 8103 | TCP 入站 | C 维修工单服务 |
| 8104 | TCP 入站 | D 身份通知服务 |

## 五、安全建议

- `.env` 中 `INTERNAL_API_TOKEN=dev-internal-token-change-me` 与 D 的
  `JWT` 密钥均为**演示占位值**，仅限彩排/答辩演示使用；
- 彩排稳定后建议收紧：
  - 云安全组 / 防火墙对 8101~8104 **限源 IP**（只放行演示场地出口 IP），例：

    ```bash
    sudo ufw allow from <你的IP> to any port 8101:8104 proto tcp
    sudo ufw deny 8101:8104/tcp
    ```

  - 或直接使用第六节的 SSH 隧道，**完全不对公网开放 8101~8104**；
- 演示结束后执行 `bash scripts/start_all.sh stop` 停止服务。

## 六、SSH 隧道替代方案（免开公网端口，最安全）

在本地电脑执行（把服务器四个端口映射到本地）：

```bash
ssh -N \
  -L 8101:localhost:8101 \
  -L 8102:localhost:8102 \
  -L 8103:localhost:8103 \
  -L 8104:localhost:8104 \
  user@<服务器IP>
```

保持该连接后，本地打开 `web/dashboard.html`，四个服务地址**保持默认
`http://127.0.0.1:810x` 不用改**，看板流量经加密隧道直达服务器。
此方式无需在安全组开放 8101~8104，仅需 22 端口。

## 七、日常运维

```bash
bash scripts/start_all.sh status   # 查看四服务健康状态
bash scripts/start_all.sh stop     # 停止四服务（按 PID，失效按端口兜底）
bash scripts/start_all.sh          # 再次启动（幂等；已在运行的服务自动跳过）
```

- 日志：`logs/A.log` ~ `logs/D.log`（`tail -f logs/A.log` 实时查看）；
- 数据：各服务 SQLite 持久化（`apps/*/member_x.db`），重启不丢历史工单/预警；
  想完全清空演示数据：`stop` 后删除各模块目录下 `*.db` 再启动；
- Python 依赖已装在仓库根 `.venv/`，与系统 Python 隔离，无需 sudo。

## 八、常见问题（FAQ）

| 现象 | 处理 |
|------|------|
| `venv 创建失败` | `sudo apt install -y python3-venv` 后重跑脚本 |
| pip 安装慢/超时 | 使用清华镜像：`.venv/bin/pip install -r apps/*/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`，然后重跑脚本 |
| `python3 版本过低` | Debian 11 请升级到 Debian 12，或自行安装 python3.10+ |
| 启动报 `address already in use` | `ss -ltnp \| grep 810x` 查占用进程；或直接 `bash scripts/start_all.sh stop` 后重启 |
| 外网访问不通（本机 curl 正常） | 检查云厂商安全组与 `ufw`/`iptables` 是否放行 8101~8104；确认监听地址是 `0.0.0.0`（`ss -ltn`） |
| 看板页面服务地址改了仍连不上 | 浏览器 F12 → Console/Network 查请求是否 CORS 或超时；确认服务器防火墙与四个地址拼写 |
