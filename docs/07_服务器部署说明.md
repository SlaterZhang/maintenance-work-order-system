# 07 · 服务器部署说明（Debian / Ubuntu）

> 目标：把"工业设备智能运维与预测性维护系统"整套跑在远程 Linux 服务器上，
> 浏览器打开看板即可演示完整的"监测 → 预警 → 工单 → 恢复"闭环。
> Windows 本机的一键脚本是 `scripts/start_all.ps1`，服务器版等价物是 **`scripts/start_all.sh`**。

## 〇、总览

| 组件 | 目录 | 端口 | 说明 |
|------|------|------|------|
| A 设备监测 | apps/equipment-monitoring | 8101 | 设备档案 + 遥测采集 |
| B 故障预警 | apps/fault-warning | 8102 | 健康评估 + 预警事件 |
| C 维修工单 | apps/maintenance | 8103 | 工单状态机 + 备件 |
| D 身份通知 | apps/integration-quality | 8104 | 登录 JWT + 用户权限 |
| 前端看板 | web/dashboard.html | — | 零构建单页，浏览器直接打开 |

四服务同机部署、互调走本机回环（127.0.0.1）。对外暴露两种方案：

- **方案二（推荐）：nginx 单端口统一入口**——公网只开 80，四服务与看板全部经 nginx
  （见第三节），uvicorn 仅绑 127.0.0.1（`start_all.sh` 默认值）；
- **方案一：直连多端口**——uvicorn 绑 0.0.0.0，公网开放 8101~8104（部署最简，
  需 `export LISTEN_HOST=0.0.0.0`，见第五节端口清单）。

## 一、前置条件

- Debian 12+ 或 Ubuntu 22.04+（python3 >= 3.10；Debian 11 默认 python3.9 不满足，请先升级系统或自装 3.10+）
- 建议 2 核 4G 内存、5G 磁盘（含依赖安装空间）
- 服务器可访问公网（首次 pip 安装依赖；也可用国内镜像，见 FAQ）
- 能 SSH 登录服务器（TCP 22 入站）

## 二、部署步骤（裸机到服务可用）

### 1. 安装系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip git curl
```

### 2. 获取代码

```bash
# 方式一：git clone（推荐）
git clone <你的仓库地址> maintenance-work-order-system
cd maintenance-work-order-system

# 方式二：本地上传（Windows 开发机打包后 scp）
# scp maintenance-work-order-system.zip user@<服务器IP>:~/
# unzip maintenance-work-order-system.zip && cd maintenance-work-order-system
```

### 3. 一键启动（自举 + 启动 + 健康等待）

```bash
bash scripts/start_all.sh
```

脚本幂等、可重复执行，首次运行会自动完成：
1. 检查 python3 >= 3.10（缺失/过低会给出 apt 安装提示并退出）；
2. 在仓库根创建共享虚拟环境 `.venv/`；
3. 按 `apps/*/requirements.txt` 安装四服务依赖；
4. 为四服务生成独立 `.env`（SQLite 数据库互不共用、内部令牌统一、
   `MEMBER_*_BASE` 指向本机回环，已存在则沿用不覆盖）；
5. 每服务一个后台 uvicorn 进程，**默认仅绑定 127.0.0.1**（nginx 方案的推荐值；
   可用 `export LISTEN_HOST=0.0.0.0` 恢复直连模式），日志写入 `logs/<代号>.log`，
   PID 写入 `.run/<代号>.pid`；
6. 轮询 `/health` 直到出现四行 `[OK  ]`（最长 60s，超时会列出未就绪服务
   并打印其日志尾部 20 行）。

### 4. 验证服务（本机）

```bash
curl http://127.0.0.1:8101/health   # ×4，全部返回 {"status":"UP",...}
bash scripts/start_all.sh status    # 随时查看四服务健康状态
```

## 三、方案二：nginx 单端口统一入口（推荐）

公网只开放 **80** 一个服务端口，四服务与看板全部经 nginx 统一入口，
uvicorn 退回仅绑 127.0.0.1（上一步的默认值），把暴露面从 4 端口缩到 1 端口：

```
浏览器 ──> :80 nginx ──┬── /            → web/dashboard.html（静态托管）
                       ├── /a/api/...    → 127.0.0.1:8101（A 设备监测）
                       ├── /b/api/...    → 127.0.0.1:8102（B 故障预警）
                       ├── /c/api/...    → 127.0.0.1:8103（C 维修工单）
                       └── /d/api/...    → 127.0.0.1:8104（D 身份通知）
```

### 1. 安装并启用

```bash
sudo apt install -y nginx
sudo cp deploy/nginx.conf /etc/nginx/sites-available/ims
sudo ln -s /etc/nginx/sites-available/ims /etc/nginx/sites-enabled/ims
sudo rm -f /etc/nginx/sites-enabled/default    # 移除 nginx 默认站点，避免抢占 80

# 按实际 clone 路径修改看板静态目录（配置内有注释说明）：
#   sudo sed -i 's#root /opt/maintenance-work-order-system/web;#root /你的路径/maintenance-work-order-system/web;#' /etc/nginx/sites-available/ims

sudo nginx -t                # 语法检查，应输出 syntax is ok / test is successful
sudo systemctl reload nginx  # 重载生效
```

### 2. 验证（经 nginx）

```bash
# 四条全部返回 {"status":"UP",...}（/a/health 剥前缀后命中后端 /health）
curl http://127.0.0.1/a/health
curl http://127.0.0.1/b/health
curl http://127.0.0.1/c/health
curl http://127.0.0.1/d/health

# 看板静态页可取（HTML 头部应含"工业设备智能运维平台"）
curl -s http://127.0.0.1/ | head -n 8

# 暴露面确认：80 监听 0.0.0.0，8101~8104 仅监听 127.0.0.1
ss -ltn | grep -E ':(80|810[1-4])\b'
```

### 3. 看板访问（方案二专用填法）

浏览器打开 **`http://<服务器IP>/`**（nginx 直接托管 dashboard.html），
页面顶部四个服务地址框填带路径前缀的形式：

```
A 设备监测  http://<服务器IP>/a
B 故障预警  http://<服务器IP>/b
C 维修工单  http://<服务器IP>/c
D 身份通知  http://<服务器IP>/d
```

登录与演示流程与第四节相同。

### 4. 回退到直连模式（或直连调试）

```bash
sudo rm -f /etc/nginx/sites-enabled/ims && sudo systemctl reload nginx  # 停用 nginx 入口
bash scripts/start_all.sh stop
export LISTEN_HOST=0.0.0.0    # uvicorn 绑 0.0.0.0，恢复 Wave4d 直连模式
bash scripts/start_all.sh     # 8101~8104 对外可达，地址框回到 http://<IP>:810x 填法
```

## 四、看板访问与演示（直连模式）

1. 在**本地电脑**浏览器打开 `web/dashboard.html`（从仓库下载该文件，或让服务器顺手起一个
   `python3 -m http.server 8090 --directory web` 后访问 `http://<服务器IP>:8090/dashboard.html`）；
2. 页面顶部四个服务地址输入框，把 `127.0.0.1` 改为 **服务器 IP**
   （如 `http://203.0.113.10:8101` ~ `:8104`）；
3. 点击「主管 USER-D-001」快捷按钮 → 登录（密码 `demo123456`）；
4. 按演示剧本操作：设备详情页「注入异常（严重）」→ 设备变红、预警产生、
   自动建单 → 主管确认/派单 → 工程师接单/维修/提交验收 → 主管验收通过 → 设备恢复绿。

## 五、端口清单（防火墙 / 云安全组放行）

| 方案 | 需开放入站端口 | 说明 |
|------|----------------|------|
| 方案二：nginx 单端口（推荐） | **80**（+22 SSH） | 四服务与看板全部经 nginx；uvicorn 仅绑 127.0.0.1 |
| 方案一：直连多端口 | **8101~8104**（+22 SSH） | 需 `export LISTEN_HOST=0.0.0.0` 后启动，用于直连调试或最简部署 |

| 端口 | 协议 | 用途 |
|------|------|------|
| 22 | TCP 入站 | SSH 部署管理 |
| 80 | TCP 入站 | nginx 统一入口（方案二） |
| 8101~8104 | TCP 入站 | 四服务直连（仅方案一，调试用） |

## 六、安全建议

- `.env` 中 `INTERNAL_API_TOKEN=dev-internal-token-change-me` 与 D 的
  `JWT` 密钥均为**演示占位值**，仅限彩排/答辩演示使用；
- 推荐方案二：公网只暴露 80，后端四端口不可直连，天然收敛暴露面；
- 彩排稳定后建议进一步收紧：
  - 云安全组 / 防火墙对 80 **限源 IP**（只放行演示场地出口 IP），例：

    ```bash
    sudo ufw allow from <你的IP> to any port 80 proto tcp
    ```

  - 或直接使用第七节的 SSH 隧道，**完全不对公网开放任何业务端口**；
- 演示结束后执行 `bash scripts/start_all.sh stop` 停止服务。

## 七、SSH 隧道替代方案（免开公网端口，最安全）

在本地电脑执行（把服务器四个端口映射到本地）：

```bash
ssh -N \
  -L 8101:localhost:8101 \
  -L 8102:localhost:8102 \
  -L 8103:localhost:8103 \
  -L 8104:localhost:8104 \
  user@<服务器IP>
```

保持该连接后，本地打开 `web/dashboard.html`，四个服务地址**保持默认
`http://127.0.0.1:810x` 不用改**，看板流量经加密隧道直达服务器。
此方式无需在安全组开放 8101~8104，仅需 22 端口。

## 八、日常运维

```bash
bash scripts/start_all.sh status   # 查看四服务健康状态
bash scripts/start_all.sh stop     # 停止四服务（按 PID，失效按端口兜底）
bash scripts/start_all.sh          # 再次启动（幂等；已在运行的服务自动跳过）
```

- **LISTEN_HOST**：uvicorn 绑定地址，默认 `127.0.0.1`（nginx 方案）；
  `export LISTEN_HOST=0.0.0.0` 恢复直连模式后需重启四服务；
- 日志：`logs/A.log` ~ `logs/D.log`（`tail -f logs/A.log` 实时查看）；
  nginx 侧日志在 `/var/log/nginx/access.log` 与 `error.log`；
- 数据：各服务 SQLite 持久化（`apps/*/member_x.db`），重启不丢历史工单/预警；
  想完全清空演示数据：`stop` 后删除各模块目录下 `*.db` 再启动；
- Python 依赖已装在仓库根 `.venv/`，与系统 Python 隔离，无需 sudo。

## 九、常见问题（FAQ）

| 现象 | 处理 |
|------|------|
| `venv 创建失败` | `sudo apt install -y python3-venv` 后重跑脚本 |
| pip 安装慢/超时 | 使用清华镜像：`.venv/bin/pip install -r apps/*/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`，然后重跑脚本 |
| `python3 版本过低` | Debian 11 请升级到 Debian 12，或自行安装 python3.10+ |
| 启动报 `address already in use` | `ss -ltnp \| grep 810x` 查占用进程；或直接 `bash scripts/start_all.sh stop` 后重启 |
| 外网访问不通（本机 curl 正常） | 方案二检查 80 放行与 `ss -ltn`（80 应为 0.0.0.0）；直连模式检查 8101~8104 放行与 `export LISTEN_HOST=0.0.0.0` 是否已设置 |
| `curl /a/health` 502/404 | 502：四服务未启动（`bash scripts/start_all.sh status`）；404：nginx 未加载 ims 站点（检查 `sites-enabled/ims` 链接与 `nginx -t`） |
| 打开 `http://<IP>/` 是 nginx 欢迎页 | 默认站点未删（`sudo rm -f /etc/nginx/sites-enabled/default` 后 reload）或未把 `default_server` 冲突处理好 |
| 打开 `http://<IP>/` 报 403 | 仓库 clone 在用户家目录时 nginx（www-data）无权穿越：`chmod o+x ~`，或按推荐把仓库放到 `/opt/` 下（nginx.conf 默认 root 即按此示例） |
| 看板页面服务地址改了仍连不上 | 浏览器 F12 → Console/Network 查请求是否 CORS 或超时；方案二确认地址框是 `http://<IP>/a` 带前缀形式 |
