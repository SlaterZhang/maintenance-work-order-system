# 接口与数据契约规范

## 1. 契约文件是唯一共识

跨模块约定统一放在：

- `contracts/openapi.yaml`：REST 接口、请求、响应与错误；
- `contracts/schemas/`：事件包络和各事件 Payload 的 JSON Schema；
- `contracts/shared-enums.json`：公共状态、风险等级和映射；
- `contracts/examples/`：可直接用于联调的示例报文。
- `contracts/http/local-api.http`：可在 VS Code 中直接执行的端到端请求。

完整端口、24 个操作、工单状态机、备件状态机和错误码见 `docs/06_详细接口约定与联调手册.md`。

聊天中的临时字段名、某个成员本地的实体类、数据库截图均不能替代契约文件。

## 2. 标识所有权

| 标识 | 生成方 | 基本规则 |
| --- | --- | --- |
| `EquipmentId` | A | 创建后稳定，不复用 |
| `WarningId` | B | 每个预警唯一，重复事件保持同一值 |
| `OrderId` | C | 每张工单唯一，创建后不可修改 |
| `EventId` | 事件发送方 | UUID，同一业务事件重试时保持不变 |
| `TraceId` | 首个业务入口 | 贯穿同一次端到端处理链 |

## 3. 版本规则

接口路径使用主版本，例如 `/api/v1/...`。事件使用 `schemaVersion`：

- 增加可选字段：可保持当前主版本；
- 新增枚举值：若旧调用方无法安全忽略，应升级版本；
- 删除字段、改字段类型或改变既有语义：必须升级主版本；
- 兼容期内提供方应同时支持新旧版本，迁移完成后再删除旧版本。

## 4. 时间、数量和空值

- 时间统一传 RFC 3339 UTC，例如 `2026-09-17T08:30:00Z`；
- 展示层按项目约定时区转换，数据库与事件保留 UTC；
- 数量不得为负；库存变化必须有不可抵销的流水；
- “字段缺失”“字段为 null”“字段为空字符串”含义不同，契约必须明确；
- 金额或精确计量不用二进制浮点直接累计，按实现语言选择 Decimal 类型。

## 5. 幂等与重试

- 事件接收方使用 `EventId` 去重；
- 同一 `WarningId` 的重发不得建立重复工单；
- 超时只表示结果未知，调用方不得立即换一个新业务 ID 重试；
- 失败重试应保留最后错误与重试次数；
- 业务写入和待发送事件应保证一致，避免业务成功但消息丢失。

## 6. 错误响应

REST 错误至少包含：

```json
{
  "code": "EQUIPMENT_NOT_FOUND",
  "message": "设备不存在",
  "traceId": "trace-20260917-001",
  "details": {}
}
```

`code` 面向程序并保持稳定，`message` 面向人员，`traceId` 用于四方定位同一链路。不要用 HTTP 200 包装业务失败。

## 7. 契约变更步骤

1. 使用 GitHub“契约变更”Issue；
2. 在 PR 中先改契约、枚举、示例和测试；
3. 至少由提供方和调用方各一人确认；
4. 实现时保留兼容策略；
5. 使用 `E2E-01` 至 `E2E-04` 场景联调；
6. D 组织端到端验证，并将最终请求、响应和执行结果脱敏后附到 PR。
